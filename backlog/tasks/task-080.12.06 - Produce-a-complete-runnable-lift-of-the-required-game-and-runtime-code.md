## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

Lowered the whole CALLOTHER atomic class: all 1,398 LOCK/UNLOCK sites in 427 bodies emit one arm64 atomic each and no body in the class keeps a hole. A region lowers only when every op is one the rewriter models (the allow-list is the 20 ops the regions actually contain: COPY, LOAD, STORE, CBRANCH, BRANCH, SUBPIECE, POPCOUNT, INT_ZEXT, INT_LEFT, the INT_BINARY and INT_COMPARE forms, and INT_CARRY/INT_SCARRY/INT_SBORROW), its accesses name one location read at least once and written once, and the address chain reaches a `ram` constant or a `unique` built only by pure ops. A region carrying a CBRANCH is a cmpxchg, because only the compare forms model the conditional store with a branch; otherwise the stored value's definition chain either reaches an INT_BINARY (read-modify-write) or leaves the region through an external varnode (exchange). Only the location accesses are rewritten: reads before the store take the atomic's old value, reads after it the stored value, the store is dropped and the atomic takes the region's first access slot, so the flags and the region-exit register file lift exactly as dumped. Op count is preserved with NOPs because Ghidra's CBRANCH/BRANCH operands are op-index offsets into the same op list. Operand ops are hoisted to the atomic's slot only when their order against everything they jump over survives, and in a compare region definitions are sought only in the prefix before the CBRANCH and in the arm holding the store; searching the whole region reads the untaken path's writes as the value's origin. Emitted kinds reconcile with the census: 758 atomicrmw add, 402 atomicrmw xchg, 205 cmpxchg, 4 atomicrmw sub, 29 atomicrmw or, at widths i32 1,210, i64 113, i8 57 and i128 18. Two decisions were made here rather than deferred. CPUID sourcing: the lifter fixes only the buffer ordering and the embedder supplies the leaf values, with scripts/lift_abi.py emitting lift_cpuid and lift_rdrand as weak definitions over lift_cpuid_leaf_at, whose built-in body declines every leaf and the default then zeroes all four registers. That fail-closed default is the only safe built-in, since a zeroed feature word sends guest code down the conservative path while an invented one lets it execute a host instruction that is not there; lift_rdrand's default is a deterministic splitmix64 stream that always claims success, and it returns _Bool because the lifter declares zeroext i1.
