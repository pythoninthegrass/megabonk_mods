1. Reference: launch the game with the megabonk MCP, screenshot a stock character (Calcium, Tony) at the character screen and in a run, and query the live Animator (parameters, state names, clip names, hips/torso hierarchy, bone count, poly count) through query_objects. Try extracting a stock character prefab and its AnimatorController from the game's asset bundles (AssetRipper or similar, output under gitignored .tools/) to get a real reference mesh and exact clip names. Record the findings in docs/characters.md.
2. Model: rebuild Squeaker in the live Blender as an upright biped (large head, ears, snout, small torso, arms, legs, curly tail) as one skinned mesh with flat toon-friendly materials, matching the stock proportions and poly budget; keep the Codex palette (warm gray, pink). Leave the backdrop, camera and lights in a separate collection.
3. Rig: armature with lowercase hips and torso bones plus limb, head, ear and tail bones, a root at the origin, and the clip set the stock Animator expects (names from step 1).
4. Cookie: separate stale cookie object, sized as a thrown projectile for the Bone-style attack.
5. Icon: render Squeaker at the character grid icon size (measure the stock icon sprite size in step 1).
6. Reference render: Blender render of Squeaker beside the stock reference for AC 1.
7. Export: FBX for the character and the cookie under unity/pack-authoring/Assets, saved .blend tracked at a repo path, scripted export steps and naming conventions documented in docs/characters.md.
8. Verify each AC, run task check, commit with a conventional message and no attribution.

Revision (user feedback): the first biped rebuild from primitives was rejected as unlike the source. Squeaker now keeps the original four-legged mouse: the sketch's parts are appended from tools/simple_mouse.blend, curves baked to mesh, joined smooth-shaded at full density into one skinned mesh, rigged as a quadruped (root, hips, torso, head, ears, four legs, three tail bones) with the stock clip names. Scripts live in scripts/blender/ and are the source of truth for the build.

Every stock character ships Idle, Run (or Walk/Moving/Running), Jump, Falling and Grind clips; frame rates 45-60, Idle 1-14 s looping, Run 0.6-1.5 s looping, Grind 0.5-1.3 s looping, Jump 0.5-1.2 s (mostly looping). Animator parameter names are unconfirmed; the string table has grounded, moving, jump, grinding, idle, slide as candidates; confirming needs a Ghidra decompile of PlayerRenderer.Update (RVA 0x3492F0, 12 min first import) and belongs to the Unity controller work in TASK-067.03. The editor free camera did not give a close in-run shot of the stock model; .tools/p1-character-screen.png is the stock visual reference so far (thin low-poly humanoids, flat toon shading, outline). No AssetRipper install exists on this box; stock mesh extraction not yet attempted.
